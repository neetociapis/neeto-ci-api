A CI job is one run of a workflow against a branch or commit of a project. For fields and response details, see the [API reference](/api/ci-jobs/create). Sample outputs on this page use `--json`.

## List CI jobs

This command shows the CI jobs of one project, most recent first. Use this when you want to find a job's ID or check what is running on a branch.

```bash
neetoci ci-jobs list --project neeto-cal-web
neetoci ci-jobs list --project neeto-cal-web --branch main --page-size 50
```

## Show a CI job

This command shows details for one CI job, including its pods. Use this when you want to check a job's status, commit, and per-pod outcome after finding its ID from `ci-jobs list`.

```bash
neetoci ci-jobs show <id>
```

- `<id>` - CI job UUID

## Trigger a CI job

This command starts a new CI job. Use this when you want to run a workflow on a branch or commit from a script or another CI system instead of pushing to GitHub.

```bash
neetoci ci-jobs create --project neeto-cal-web --branch main --workflow playwright
neetoci ci-jobs create --project neeto-cal-web --branch main --workflow playwright \
  --commit 9b1d4e7f2a3c5d6e8f0a1b2c3d4e5f6a7b8c9d0e
```

<CiJobsCreateFlags />

`--workflow` is the workflow's config file name without `.yml`, for example `playwright` for `.neetoci/playwright.yml`. `--commit` defaults to the latest commit on the branch.


</Tip>

## Cancel a CI job

This command cancels a CI job. Use this when you want to stop a queued or running job without opening NeetoCI.

```bash
neetoci ci-jobs cancel <id>
```

**Required arguments:**

- `<id>` - CI job UUID

```json Sample output (--json)
{
  "data": {
    "notice_code": "thumbs_up"
  }
}
```

The response confirms the request. Run `ci-jobs show` to see the job's final status.

## Rerun a CI job

This command reruns a CI job on the same commit and workflow. Use this when a job failed for a reason unrelated to the code, such as a flaky test or an infrastructure error.

```bash
neetoci ci-jobs rerun <id>
```

**Required arguments:**

- `<id>` - CI job UUID

```json Sample output (--json)
{
  "data": {
    "notice_code": "thumbs_up",
    "message": "Please wait while we rerun the job."
  }
}
```

The rerun is queued in the background, so the response does not include the new job. Run `ci-jobs list` for the project to find it.

## Show CI job logs

This command lists each pod of a CI job with a download URL for its log file. Use this when you want to read the output of a finished job or attach it to a bug report.

```bash
neetoci ci-jobs logs <id> --project neeto-cal-web
```

- `<id>` - CI job UUID

## Show resource metrics

This command shows the CPU and memory a CI job's pods used while running. Use this when a job was killed for running out of memory or took longer than expected and you want to see which pod hit its limits.

```bash
neetoci ci-jobs resource-metrics <id> --summary
neetoci ci-jobs resource-metrics <id> --metric memory --pod neetoci-169bf1ed-0 --step 60
```

**Required arguments:**

- `<id>` - CI job UUID

<CiJobsResourceMetricsFlags />

```json Sample output (--json, with --summary)
{
  "data": {
    "ci_job_id": "169bf1ed-cc65-471f-b9f3-4f63f32b9400",
    "containers": [
      {
        "container": "production-169bf1ed-cc65-471f-b9f3-4f63f32b9400",
        "pods": [
          { "pod": "neetoci-169bf1ed-0", "peak_cpu": 82.4, "peak_memory": 3221225472.0 },
          { "pod": "neetoci-169bf1ed-1", "peak_cpu": 76.9, "peak_memory": 2952790016.0 }
        ]
      }
    ]
  }
}
```

Without `--summary`, each pod also carries `cpu` and `memory` arrays of `{ "timestamp", "value" }` points. CPU values are a percentage of the pod's CPU quota and memory values are bytes; `timestamp` is in Unix seconds. The window defaults to the job's start and end times and `--step` defaults to 15 seconds.
